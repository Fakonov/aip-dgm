# 元祖暴龙机 · 屏幕版式分析

> 数据来源：把 `ref/assets/DigimonV1J.svg`（MAME 用的 4028×2692 正视图）用 headless Edge 按 1:1 渲染成 PNG，再在像素上量的。不是目测，也不是照抄别人的说法。

（结构图未随仓库分发：由 `ref/vpet_v1v2v3/make_layout.py` 从参考 SVG 重新渲染）

---

## 1. 一句话概括

**一块玻璃，三条带，共用同一套段驱动。**

同一条 LCD 玻璃被切成三段：上功能区（4 枚图标）、中间 32×16 游戏点阵、下功能区（4 枚图标）。三条带的**横向宽度完全一致**，都是 32 列；图标不是印上去的丝印，是和点阵同源、同一张段表刷新出来的可寻址段。

---

## 2. 实测数据

单位：渲染图像素（1 格 = 39.2 px）。

| 部件 | 范围 | 尺寸 | 折算成格 |
|---|---|---|---|
| 上功能区 | y 787–940 | 高 154 | 3.9 格 ≈ **4 格** |
| ↕ 玻璃留白 | y 941–1035 | 95 | 2.4 格 |
| 游戏点阵 | x 718–1975，y 1036–1660 | 1258 × 625 | **32 × 16 格** |
| ↕ 玻璃留白 | y 1661–1757 | 97 | 2.5 格 |
| 下功能区 | y 1758–1913 | 高 156 | **4 格** |
| 整块玻璃 | y 787–1913 | 1258 × 1127 | 32 × 28.7 格 |

点阵本身：列距 39.31、行距 39.06（≈ 正方形单元），单格墨块 36×36，格间孔隙 ≈ 3.3 px。**宽高比 1258 : 625 = 2.01 : 1**，正好等于 32 : 16。

---

## 3. 三条带的对齐关系

| 关系 | 实测 | 含义 |
|---|---|---|
| 带宽 = 画面宽 | 三条带 x 范围同为 718–1975 | 布局上就是同一个 32 列坐标系，不是"差不多宽" |
| 图标等分 | 上带 4 枚中心 x = 914 / 1202 / 1494 / 1778 | 间距 ≈ 288 px ≈ 7.3 格，四等分 |
| 每枚 ~8 列 | 32 列 ÷ 4 枚 = 8 列/枚 | 图标 ink 只占槽位 60~65%，两侧留白 |
| 带宽 = 4 格 | 154 / 39.2 = 3.9 | 图标带高度正好是 4 个点阵行高 |
| 带与点阵不相邻 | 中间有 2.4 格玻璃留白 | **不是点阵的第 0 行/第 17 行**，是玻璃上的独立电极区 |

最后一条最容易踩坑：很多人会把图标当成"第 0 行和第 17 行的点阵"来画，结果整屏高度算成 18 行、图标被压扁。它不是。

## 4. 段结构：为什么图标画不进帧缓冲

| 项 | 数值 |
|---|---|
| 点阵可寻址段 | 32 × 16 = **512**（byte 0x02–0x99，bit 0–3） |
| 图标段 | **+8** = 520（byte 0x00/0x12/0x14/0x16，以及 0x89/0x9B/0x9D/0x9F 一带） |
| 编码 | `cell = byte \| (bit << 8)` |

8 个图标段全部落在 512 点阵的 byte 区间之外，也就是说：

- 它们和点阵**共用同一张段表**，一次刷新就能同步更新；
- 但它们**不在 32×16 的 XY 坐标系里**，没有行列号，只有 bbox。

所以正确渲染顺序是：

```
段刷新 → 铺 32×16 点阵像素 → 按 bbox 叠 8 枚图标贴图 → 整屏缩放
```

反过来"把图标写进 framebuffer 再一起缩放"必然错位——图标是矢量/贴图，点阵是像素，缩放采样规则不同。

## 5. 八个图标（按图形识别）

| 位置 | 图形 | 推测功能 | 置信度 |
|---|---|---|---|
| 上 1 | 仪表盘/量表 | 体力或状态量表 | 高 |
| 上 2 | 带骨肉 | 食物 | 高 |
| 上 3 | 人击打沙袋/瓶状物 | 训练 | 中 |
| 上 4 | 两个交手的人形 | 对战 / 通信对战 | 高 |
| 下 1 | 层叠堆状物 | 便便 / 扫除 | 高 |
| 下 2 | 带光芒的灯泡 | 呼叫 / 注意 | 高 |
| 下 3 | 交叉的条状物 | 医疗 / 药品 | 中 |
| 下 4 | 闪电击向半圆 | 必杀 / 死亡 | 低 |

与 ROM 侧对得上：`mode` 0 家、1 对时、**2–8 七个菜单**、9 进化、A 便便、B 死亡、C 墓碑。七个菜单对应七个图标段，第八段（0,0）是孵化时常亮的那枚。

**置信度低的两项要真机确认**，别直接写进文档当结论。

## 6. 对渲染/UI 的硬约束

1. **画布必须是 32 : 28.7 的玻璃比例**，不是 2:1。只取游戏区才用 2:1。
2. **缩放只允许整数倍**（×4 / ×6 / ×8）。点阵单元 36 px + 3.3 px 缝，非整数倍会让缝宽变成 3 或 4，摩尔纹立刻出现。
3. **图标不能挤压点阵**：加图标带只能加在点阵上下方的留白里，且留白 ≥ 2.4 格。
4. **图标槽位 8 列/枚**，ink 居中，两侧留白对称——这就是"图标带看起来没顶满"的原因，别把图标拉到槽宽 100%。
5. **上下带同高**（4 格）。只给上面加带、下面不给，整块屏重心就偏了。
